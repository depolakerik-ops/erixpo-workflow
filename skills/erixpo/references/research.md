# Research pass

Do this before recommending tools, a stack, or a UI kit. Write `.erixpo/research.md`.
Agnostic: site, app, script, firmware, wiki, inbox pipeline, slides. Research that job.

## Order

1. Read the repo. Prefer lockfiles over a blog post.
2. Classify repo domain and request separately.
3. Live-search this year: language, framework or none, data or none, UI kit, test runner, lint, build/deploy if they ship.
4. Skill hunt — list, do not install.
5. MCP hunt only if the worker lacks a surface — propose, do not install.
6. 2–4 options + boring official default + "do nothing extra" when a kit/db is optional.

## Tools section

Build / Test / Lint / UI / Deploy / why not the fashionable alternative. Cite current-year sources.

## Hard rules

Landing page gets no database just in case. Embedded gets no Tailwind. SwiftUI does not use Playwright as the primary test. Writing repos get no SaaS stack.

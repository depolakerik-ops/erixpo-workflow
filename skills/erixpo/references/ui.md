# UI conversation

If the work has no surface (CLI-only script, rename job, research note), skip this file.
If humans will see or touch something, you do not pick a look alone.

## Talk first

Ask only what changes the look:
- Who looks at it?
- A reference they like, or "I don't care, you propose"?
- Density: sparse marketing vs dense tool vs native platform chrome
- Must match an existing design system? If the repo already has tokens, use those.

Then propose 2–3 directions with a sentence each + one default. Wait.

## Research the UI kit for this surface and year

Do not default to Tailwind + shadcn + purple gradient.
Write `.erixpo/research.md` ## UI: surface, platform guide, 2–4 kit options, empty/error/loading, what you will not do.

## During implementation

Empty, error, loading, disabled, first-run with the happy path when cheap.
No Inter-everywhere dashboard or fake testimonials unless they asked.
Taste from `.erixpo/USER.md` wins.

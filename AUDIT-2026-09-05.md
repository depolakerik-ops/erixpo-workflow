# erixpo-workflow audit — 2026-09-05

Reviewed at commit `3bd5c62`, pack version `0.6.2`. This is an assessment, not an implementation patch. Existing `.serena/` content was left alone.

## Assessment

The project has a coherent direction: a portable, repository-adaptive workflow that remembers the human, handles different kinds of work, and carries approved work through implementation, verification, review, and cleanup. The strongest ingredients are the single router, platform-sensitive scaffolding, bounded memory, proportional documentation, and explicit separation of implementation from review.

The main weakness is the gap between instructions and enforcement. The skills describe a dependable autonomous workflow; the executable layer still permits premature success, destructive cleanup, and broken updates. A reliability release should precede additional integrations or broader autonomy.

Keep the runtime small. Let skills handle judgment, let the runtime own lifecycle guarantees, and let evaluations determine whether the methodology actually improves outcomes.

## Release blockers

### 1. Reinstallation removes the installed CLI — P1, reproduced

Location: [install.sh:79](/Users/erikpolak/Desktop/erixpo-workflow/install.sh:79), installation ordering at line 94.

Install twice into the same empty target. Both commands exit zero, but after the second install `.erixpo/bin/erixpo` is missing. `bin` already points to `.erixpo/bin`; legacy cleanup removes `bin/erixpo` through that symlink **after** the new CLI was copied.

Fix: distinguish owned legacy files from current symlinks; migrate before copying; verify the final CLI executes before reporting success. Install into a staging directory and preserve the previous working version until validation succeeds.

Acceptance: fresh install, same-version reinstall, host expansion, and upgrade all leave an executable CLI and preserve user files.

### 2. Close silently discards uncommitted work — P1, reproduced

Location: [scripts/worktree.sh:185](/Users/erikpolak/Desktop/erixpo-workflow/scripts/worktree.sh:185), called by `cmd_close` at line 429.

Created an isolated tree, changed a tracked file and added an untracked file, then closed it. Close exited zero and deleted both changes. The branch tip was already contained in the parent, so the ancestry check passed. `git worktree remove --force` then discarded the working directory. The existing dirty check examines the destination checkout, not the source worktree.

Fix: inspect the source worktree before any merge/removal; refuse staged, unstaged, or untracked user work. Normal close should use Git's normal removal protections. An explicit discard operation must be distinct from close. Apply the same principle to prune and bulk uninstall cleanup.

Git documents that normal removal refuses an unclean worktree and `--force` bypasses that protection. [Git worktree documentation](https://git-scm.com/docs/git-worktree.html)

### 3. A passing baseline check terminates unfinished plans — P1, reproduced

Location: [bin/erixpo:351](/Users/erikpolak/Desktop/erixpo-workflow/bin/erixpo:351).

An approved plan contained two incomplete slices. A generic worker exited 7 without completing either. The existing check passed, and the outer loop exited zero on iteration one. The loop never validates the plan's completion, slice evidence, or the `ERIXPO_DONE` convention. It will similarly stop after the first successful slice of a larger plan.

Fix: distinguish `slice_verified`, `plan_complete`, `blocked`, `worker_failed`, and `budget_exhausted`. Require successful worker execution, remaining-work validation, and fresh evidence before plan completion. A green baseline is a prerequisite for continuing work, not proof that requested work exists.

Keep `state.md` canonical as the project requires. Define a strict parseable schema within it and explicit per-slice status in the plan; avoid introducing a competing state writer.

### 4. Installer ownership is inferred from filenames — P1, reproduced

Location: [install.sh:79](/Users/erikpolak/Desktop/erixpo-workflow/install.sh:79), [install.sh:123](/Users/erikpolak/Desktop/erixpo-workflow/install.sh:123).

A pre-existing project `scripts/worktree.sh` was replaced by the pack version despite having unrelated contents. Legacy cleanup deletes known basenames without verifying provenance. Separately, `--purge-docs` deleted a pre-existing user document with an empty `init-manifest.txt`; the implementation never reads that manifest, although init promises deletion only of files it created.

Fix: record ownership and installed hashes, preserve modified or unknown files, and use the init manifest for generated documents. Check symlink ownership and parent-path containment before deletion. Do not silently replace unrelated symlinks either.

### 5. Default review can fail because erixpo installed itself — P1, reproduced

Location: [scripts/review-stage1.sh:167](/Users/erikpolak/Desktop/erixpo-workflow/scripts/review-stage1.sh:167).

A fresh generic installation with a valid fixture check failed stage 1 for `TODO: implement or lorem ipsum`. The recursive scan includes installed skill prose containing the forbidden examples; its exclusions do not cover those directories. Recursive symlink traversal also exposes pack scripts through compatibility links.

Fix: establish an explicit set of project files, exclude owned pack content and generated/vendor artifacts, and scan relevant source rather than arbitrary recursive text. Include positive tests proving that an installed, valid project passes review.

## Lifecycle and architecture improvements

**Preserve memory when closing a worktree.** Isolation copies `.erixpo/` into the child, but close only merges Git commits and removes the directory. Under the documented policy that `.erixpo/` is untracked, child sessions, learnings, progress, and updated preferences are lost. Reconcile child state before deletion: deduplicate session/learning events by ID, retain provenance, and detect conflicts in mutable USER/MEMORY files. A close test should prove that a learning captured in a child is searchable from the parent afterward.

**Bind review to the artifact reviewed.** Review output currently records a base but does not establish a checked head/tree digest. Close does not enforce stage-1 pass or stage-2 `ship`. Record base, head, dirty-tree digest where appropriate, check command, result, and reviewer identity. Recheck when code changes after review. User authorization to merge remains separate from technical review status.

**Make state transitions atomic.** Registry updates truncate and rewrite JSONL without locking or atomic replacement. Concurrent runs can lose updates, and interruption can corrupt state. Use a cross-platform lock and write-to-temp plus atomic rename. Record the originating branch and base commit at isolation so merge targets and review ranges are explicit. Reconcile registry state against `git worktree list` after interruption.

**Preflight before creating worktrees.** Confirm worker availability, plan status, check configuration, and runtime requirements before allocating a tree. Add wall-time limits, reliable signal propagation, and failure classification. The current failure counter measures consecutive worker exit failures, not repeated check failures. A successful worker can repeat the same failing check until the iteration cap.

**Make adapter support testable.** Current adapter checks inspect source strings rather than invocation behavior. Use fake provider executables to verify working directory, prompt bytes, arguments, exit-code propagation, and interruption. Add an adapter capability declaration for headless execution, available tools, structured output, and budget reporting. Test real supported CLI versions periodically; distinguish skills compatibility from verified unattended-run compatibility.

**Separate durable project knowledge from local runtime files.** The blanket instruction never to commit `.erixpo/` puts constitutional rules, preferences, and reusable knowledge in the same category as engine copies and logs. Define which knowledge should be shared or exported and which state is machine-local. Preserve a single authority for each fact.

## Reduce contradictory instructions

These are maintenance defects, not reasons to add more prose:

- The canonical state is `state.md`, but `templates/.erixpo/` contains `state.yaml` and no `state.md`; worktree isolation still appends to YAML. Consolidate templates and add a migration fixture.
- Research says memory cannot skip a build search, then says it can downgrade narrow to skip. Define one policy.
- Research flags such as `unknown_api` are checked after the non-build early return; a fix with an unknown API still returns skip. Check explicit evidence needs first.
- Feature dependency approval rules differ from the general autonomy table. Centralize autonomy policy and reference it from tracks.
- `INSTALL.md` says global install never touches the current project, while `do_install` performs local installation before global copies. Global removal also lacks symmetric tracking.
- `budget.md` exists, but the CLI does not read its budget fields. Either enforce each advertised field or mark it as agent guidance.
- Changes after the listed 0.6.2 release still share version 0.6.2. Version-only update detection cannot distinguish them. Publish immutable releases and record the installed commit as provenance.

Make check commands and protocol examples executable documentation tests. Check all reference links, template identities, and state enums, not only skill frontmatter and selected grep markers.

## Product direction

My suggested promise is: **“A portable workflow that remembers how you work and carries approved tasks through verifiable completion.”**

Preserve the broad domain model, but validate a small set of representative journeys before claiming equivalent quality everywhere: an existing codebase feature, a native app change, a small automation, and a writing/research artifact. The architecture can remain general while support evidence becomes specific.

Make the light path substantially lighter. Even light init currently has numerous mandatory files. A one-shot writing task should not require a full repository brain before producing value. Grow persistent context when the work recurs or needs handoff.

Make research respond to uncertainty, dependency versions, explicit references, and stale evidence. Mandatory current-calendar-year searches for every small build slice can add time without improving the result; current official documentation may also be undated. Cache useful findings with version and access date, and evaluate when refreshing them changes outcomes.

Replace aesthetic prohibitions as the main quality signal with observable criteria: task completion, hierarchy, density, accessibility, platform conventions, consistent states, and human preference. Keep taste defaults overrideable. Use preview evidence and calibrated visual review when the surface warrants it.

## Evidence-based development

Build two distinct suites:

1. **Deterministic runtime contracts:** install/update/uninstall ownership, worktree safety, root handling, state persistence, loop termination, timeout recovery, and adapter invocation. Run on Linux and macOS, including paths with spaces and the supported Bash/Python versions.
2. **Behavioral evaluations:** fixed user requests in representative repositories, with checks of the resulting artifacts. Measure completion, false success, user intervention, regressions, elapsed time, and cost where available. Compare the same model with and without erixpo; record model and pack versions and repeat trials.

Specific evaluation cases: continue a two-slice plan across sessions; recover from a worker failure; review without editing; update README without reinstalling; remember a correction after closing a worktree; finish a writing task without software scaffolding; identify macOS SwiftUI correctly.

Use these results to remove workflow steps that do not help. Anthropic's harness work supports incremental progress with durable handoff artifacts, and its later work explicitly tests simplification as models improve. This is supporting evidence for the direction, not proof of erixpo's effectiveness. [Long-running agent harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents), [harness simplification](https://www.anthropic.com/engineering/harness-design-long-running-apps)

Outcome checks matter more than completion claims. Combine deterministic grading with human-calibrated judgment for subjective outputs. [Agent evaluation guidance](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

The existing router/reference split aligns with progressive disclosure. Continue reducing eager reference loading and duplicated rules; the specification recommends focused resources loaded only as needed. [Agent Skills specification](https://agentskills.io/specification)

## Suggested release order

1. **Safety and installation:** repair reinstall, ownership, dry run, source-tree protection, canonical CLI access, and installed-project review; add reproductions as regression tests.
2. **Dependable execution:** completion semantics, root/subcommand parsing, reviewed-artifact identity, durable memory reconciliation, atomic state, preflight and cancellation.
3. **Measured quality:** adapter contracts, Linux/macOS CI, representative end-to-end evaluations, simplified instructions, versioned releases, and a truthful support matrix.

Defer new issue integrations, a web console, and additional orchestration until the installed workflow reliably survives that lifecycle. Sandbox work becomes more valuable when its threat model and adapter permissions are explicit; it does not substitute for safe cleanup and truthful completion.
